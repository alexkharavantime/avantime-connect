# Выдача WireGuard-конфигурации для Mac — админка 0.5.2

В админке откройте «Пользователи» → нужный пользователь → «WireGuard для Mac».
Введите понятное имя устройства, например `Oleg-MacBook`, и проверьте DNS.
Значение по умолчанию `10.40.0.10` соответствует DNS, включённому в текущую
серверную политику DEV/PROD. Другой DNS должен быть доступен по выданным маршрутам.
Нажмите «Создать конфигурацию», дождитесь подтверждения регистрации и скачайте
`Avantime-Mac.conf`. Короткое имя файла совместимо с именем туннеля WireGuard.
Перед выдачей запрашивается текущий подтверждённый профиль, а не только снимок
первоначальной регистрации. Если устройство уже отозвано или изменение доступа
не подтверждено сервером, файл не выдаётся.

На Mac установите WireGuard, импортируйте файл через Import tunnel(s) from file
и нажмите Activate. Затем проверьте доступ к нужному серверу по DNS-имени и запуск
существующего RemoteApp `.rdp` через Microsoft Windows App.

## Ключи и повторная попытка

Ключи X25519 создаются в браузере администратора. Требуются HTTPS (или localhost)
и браузер с Web Crypto X25519. При отсутствии поддержки операция прекращается
до создания приглашения. Приватный ключ не передаётся API, не сохраняется в
MongoDB, localStorage или sessionStorage. Он содержится в памяти вкладки и
скачанном файле; передайте файл защищённым способом только владельцу Mac.

Это создание нового устройства, а не экспорт ключа существующего Windows-клиента.
Регистрация использует существующие приглашения, IPAM, серверное применение
peer и политик доступа, журнал enroll и обычный отзыв устройства. Скачивание
локального файла не является отдельным серверным событием аудита.

При сетевой ошибке не обновляйте страницу. «Повторить регистрацию» использует
те же ключи, токен и имя. При подтверждённом успехе файл доступен для повторного
скачивания, пока форма открыта. Переключение разделов и повторный ввод ключа
администратора форму не уничтожают. Закрытие страницы предупреждает о потере
данных, но браузер не гарантирует такое предупреждение при аварийном завершении.

После закрытия формы/страницы восстановить приватный ключ на сервере нельзя.
При потере файла проверьте раздел «Устройства», отзовите созданное или ожидающее
устройство и создайте новое. При истёкшем окне восстановления или отозванном
устройстве повторный enroll не обходит ограничения сервера.

## Изменение доступа

Статический `.conf` не выполняет функцию Windows-клиента «Обновить доступ».
Сужение доступа применяется серверной политикой. Для расширения маршрутов после
смены DEV/PROD администратор должен обновить AllowedIPs в существующем профиле
согласно назначенному доступу либо отозвать старое устройство и выдать новое.
Не обещайте автоматическое обновление файла на Mac.

## Проверка перед выпуском

Автоматические тесты: соответствие публичного ключа экспортированному приватному,
формат файла и маршруты, запрет внедрения строк конфигурации, отсутствие приватного
ключа в API, повтор после потери ответа, сохранность формы при навигации.

На тестовом Mac отдельно проверить импорт, handshake, DNS, RemoteApp, доступ
DEV/PROD согласно назначению и прекращение доступа после отзыва. Эти проверки
требуют реального VPN-сервера и Mac и не заменяются unit-тестами.

## Установка обновления

Готовая сборка интерфейса доступна в GitHub Actions → Server access checks →
Artifacts → `AvantimeConnect-Admin-0.5.2` после успешного запуска проверок.

Для полного обновления существующей установки на `avg-connect-dev` используйте
отдельный checkout проверенного коммита выпуска. Из его корня под пользователем
`alex` выполните:

```bash
sudo -v
python3 deploy/admin/update-0.5.1.py --release 0.5.2
```

Имя скрипта сохранено для совместимости; параметр `--release` выбирает версию.
Скрипт рассчитан на существующую установку `avantime-connect-runtime-0.4.0`
с контейнерами `avantime-connect-wg-*` и сайтом `/var/www/avantime-connect`.
При несовпадении структуры не обходите проверки: сначала уточните размещение.
Скрипт собирает интерфейс и API, сохраняет резервную копию compose, MongoDB и
сайта, перезапускает API и проверяет опубликованные HTTPS-файлы. При ошибке
публикации восстанавливает предыдущий API и главную страницу. MongoDB автоматически
из резервной копии не восстанавливается. Путь резервной копии выводится в терминале.

После обновления обновите страницу без кэша: в заголовке должна быть версия
`0.5.2`. Проведите проверку тестового устройства Mac и его отзыва, прежде чем
выдавать профили пользователям. Разработка и автоматические проверки сами по
себе не означают, что обновление уже установлено на рабочем сервере.
