# Админка и журнал доступа 0.5.1

Обновлять нужно frontend и backend вместе; Windows-клиент остаётся 0.5.0.
В заголовке веб-интерфейса виден номер 0.5.1, на вкладке Пользователи —
Компьютеры / VPN-IP, добавлена вкладка Журнал доступа.

Журнал фиксирует приглашения, попытки регистрации, изменения/повторы применения
доступа и отзывы через API. До операции сохраняется запись с неподтверждённым
результатом, после ответа — результат и HTTP-код. При сбое записи намерения
операция не начинается; при сбое записи результата возвращается 503 с предупреждением,
что операция могла выполниться. После падения процесса запись остаётся неподтверждённой.
Повторные запросы являются отдельными попытками, а не новыми выдачами IP.
Ошибки 502 и 503 не доказывают отсутствие изменений на VPN-сервере.
Журнал не является журналом соединений/handshake и не видит ручные изменения в MongoDB/SSH.

Для старых устройств импортируются только completed_at и revoked_at, если они есть,
с отметкой «Из прежних данных». Импорт идемпотентный и ограничен датой первого запуска
журнала. Старые права и неизвестные даты не выдумываются.
Токены и публичные/приватные ключи в журнал не включаются. Доступ к журналу и CSV —
по существующему административному ключу. Персональное авторство невозможно при общем ключе.
События хранятся в MongoDB без TTL и входят в mongodump; API удаления журнала не добавлено.
Это не криптографически защищённый архив: администратор MongoDB может менять данные.

Фильтры: точный логин и даты (границы по локальному времени браузера, события показываются
в UTC). Экран: по 100 записей; печать/PDF и CSV: весь выбранный период.
При печати верхняя граница фиксируется временем запроса. Результат незавершённой операции
может уточниться во время выгрузки. CSV защищён от формул в полях пользователя.

## Установка

На avg-connect-dev получить отдельный checkout нужного commit в новой папке.
Выполнить sudo -v, затем python3 deploy/admin/update-0.5.1.py из checkout.
Скрипт читает реальные параметры контейнеров и проверяет nginx. Собирает frontend
и API, сохраняет Compose, mongodump и /var/www/avantime-connect. Перезапускает только
API, затем публикует assets и атомарно заменяет index.html в /var/www/avantime-connect.
Старые assets сохраняются, чтобы уже открытые вкладки продолжали работать.
При ошибке возвращает прежний index.html и Compose/API; базу не перезаписывает.
Контейнер UI не перезапускается: публичный сайт обслуживается nginx из статической папки.
WireGuard/helper, ключи, выдача IP и права не меняются.
Проверки: API health, образ API и окружение, авторизованный запрос журнала,
HTTPS connect.avantime.lv через loopback с проверкой сертификата, точное совпадение
index.html и JS с новой сборкой, /api/health через nginx.
После установки обновить страницу: в заголовке должно быть 0.5.1.
Скрипт ещё не запускался на рабочем сервере; локально проверены синтаксис,
публикация статических файлов и возврат прежнего index.html.
